# 茶山经营 · 制茶工坊

把"点按钮出茶叶"升级为完整的种—采—制—评模拟：茶园按海拔、坡向、天气长芽，
制茶分萎凋、杀青、揉捻、发酵、烘干等工序，玩家逐道控温控时，叶子的含水率与
氧化程度按分钟级物理曲线变化，做坏会出现焦边、红梗、酸馊等缺陷，评茶师按
外形、汤色、香气、滋味四维打分并**把问题归因到具体工序**。

## 技术栈

- TypeScript + Vite，零运行时第三方依赖
- 纯函数引擎（生长/制茶/缺陷/审评），主线程、Web Worker、测试共用同一套实现
- 工序模拟与整季生长结算运行在 Web Worker 中，UI 不阻塞
- Vitest 锁定两条硬指标

## 四个页面

| 页面 | 内容 |
| --- | --- |
| 🏔️ 茶山地图 | 百园 SVG 地图（颜色=物候期）、60 天天气带、地块详情（积温/土壤水分/胁迫曲线）、按采摘标准与日期采鲜叶 |
| 🍵 制茶车间 | 选鲜叶批次与六大茶类，逐道工序用滑杆控温控时，Worker 实时推送含水率/氧化/热损伤读数与曲线 |
| 🧐 评茶 | 四维评分、缺陷明细、**工序问题归因（哪道工序、为什么）**、实际 vs 参考工艺双曲线、逐工序偏差表 |
| 📦 茶仓 | 成品库存、茶类筛选、评分汇总、下架管理 |

状态通过 localStorage 持久化，顶部可换季节种子重开。

## 领域模型

```
src/engine/
  climate.ts        春茶季气候状态机(晴/多云/雨/雾/霜，气温/降水/湿度/日照)
  garden.ts         100 块程序化茶园(海拔 220~1180m、坡向、坡度、土壤、雾况)
  growth.ts         日结算: 有效积温 GDD、土壤水分平衡、旱/热/渍/霜胁迫、物候期、采摘质量
  processing.ts     分钟级制茶物理: 脱水、酶热钝化、酶促/非酶氧化、热损伤
  defects.ts        22 条工序缺陷规则(焦边、红梗、酸馊、烧堆…)，全部带工序归因
  evaluation.ts     四维等权评分 + 最重工序归因
  data/cultivars.ts 8 个编拟茶树品种(积温需求、抗旱性、适制茶类加成)
  data/recipes.ts   六大茶类参考工艺表(参考温时、出口含水率/氧化、脱水标定常数)
src/workers/
  sim.worker.ts     Worker: 制茶流式模拟 + 整季生长结算
  SimWorkerClient.ts Promise 化的 Worker 客户端
```

### 制茶物理要点

- **脱水**：每道工序携带自动标定的脱水系数 `refDryK`（`scripts/autofit.ts` 反解），
  玩家调时长按时长反比补偿，调温度由温度驱动因子响应。
- **氧化**：萎凋/做青/揉捻/发酵走酶促路径（受酶活、温度钟形门限、含水率门限约束），
  闷黄/渥堆走非酶微生物路径；杀青 >70℃ 指数钝化酶活。
- **缺陷**：每条规则绑定一道工序，评茶时按扣分聚合，`blamedStage` 指出问题最大的工序。

## 两条硬指标（测试强制）

1. **参考工艺含水率曲线偏差 ≤ 3 个百分点**：实际标定后六大茶类最大偏差 0.83pp；
   做坏批次在评茶页明确归因（`tests/defect-attribution.test.ts` 覆盖红梗、焦边、
   酸馊、干度不足、死青、多工序出错 6 种场景）。
2. **100 块茶园整季结算 < 1 秒**：实测 0.94~3.46ms（`tests/growth-performance.test.ts`，
   基准脚本 `scripts/bench.ts`）。

## 命令

```bash
npm install
npm run dev        # 开发服务器
npm run build      # 类型检查 + 生产构建(Worker 单独分包)
npm test           # 25 个测试
npx tsx scripts/bench.ts       # 性能基准
npx tsx scripts/calibrate.ts   # 工艺标定核对
```

## 试玩路径

1. 茶山地图 → 「开始整季生长结算」（Worker，毫秒级完成 100 地块 × 60 天）
2. 点一块成熟地块 → 选采摘标准与日期 → 采摘鲜叶
3. 制茶车间 → 选批次与茶类 → 先用「一键填入参考工艺」跑一批合格茶
4. 再故意把杀青温度调到 120℃ 或把发酵温度拉到 40℃，看评茶页如何归因
5. 茶仓查看库存与各批次评分
